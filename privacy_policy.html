ABOUT THIS APPLICATION ======================================== আমাদের দেবিদ্বার is an independent, non-commercial, community-driven mobile application developed to assist the residents of Debidwar Upazila, Cumilla, Bangladesh. The application provides access to local service directories, union information, emergency contacts, prayer times, delivery services, and other community resources, all in one place. This application is developed and maintained by an individual developer as a voluntary public service initiative. It is not a commercial product and does not generate any profit from user data. IMPORTANT: This application does NOT provide any government services, does NOT link to any government websites, and does NOT collect or use any information from government portals or official databases. All information within this app is sourced entirely from local community volunteers and publicly available listings. ======================================== 2. INFORMATION WE COLLECT ======================================== 2.1 Information Provided Voluntarily by Users The application may collect the following information directly from the user during initial setup or when using certain features: User Name: The user's name is collected voluntarily during the initial setup screen (WelcomeActivity). This is stored locally on the user's device to personalize the experience, such as displaying a greeting on the home screen. Union Name: The user selects their union from a list of 16 unions/municipality (union) areas in Debidwar Upazila. This is stored locally on the device to display relevant local services and providers based on the user's area. Ward Number: Entered only when the user manually uses the delivery service feature to identify the delivery area. Important Storage Notice: All of the above information is stored exclusively on the user's own device using Android SharedPreferences. This information is never transmitted to any developer-owned server, cloud database, or third-party database. The developer has no access to this information at any time. ---------------------------------------- 2.2 Location Information ---------------------------------------- The application requests access to device location data only when the user explicitly chooses to use the Delivery Service feature (DeliveryActivity). Location access is triggered only when the user taps the Send Location button within the Delivery Service screen. Location permission is requested at runtime. The user must actively grant permission before any location data is accessed. The obtained location coordinates are converted into a Google Maps link and shared through WhatsApp, only to facilitate the user's delivery request. The developer does not store, record, or maintain any database of user location information. Background location tracking is never performed. The application does not access location when running in the background. Users may deny or revoke location permission at any time through device settings. To revoke location permission: Settings > Apps > আমাদের দেবিদ্বার > Permissions > Location > Deny ---------------------------------------- 2.3 Favorites Data ---------------------------------------- When the user saves a service provider using the Favorites button, the provider's name, phone number, WhatsApp number, address, and category are saved locally on the device using Android SharedPreferences. This data never leaves the user's device and is not accessible by the developer. ---------------------------------------- 2.4 Provider Submission Data ---------------------------------------- The application includes an "Add Provider" feature, available under union service lists and bazar category lists, that allows users to voluntarily submit information about a new service provider for the community directory. When a user submits this form, the following information is collected: the provider's name, phone number, WhatsApp number (optional), address, and the relevant union, ward, and service or bazar category. This submitted information is sent directly to a private GitHub Issue within the developer's repository for manual review. The developer personally reviews each submission before deciding whether to add it to the public community directory or reject it. This feature does not create a user account and does not collect any identifying information about the person submitting the form (such as their own name or device details) — only the information entered about the suggested provider is transmitted. ---------------------------------------- 2.5 Rent and Sale Listing Submission Data ---------------------------------------- The application includes an "Add Listing" feature, available under the "Rent and Sale" (বাসা ও দোকান ভাড়া) section, that allows users to voluntarily submit a listing for a house, office, shop rental, or land sale. When a user submits this form, the following information is collected: a title, rent or price, area, union (optional), address, additional details (optional), phone number, and WhatsApp number (optional). This submitted information is sent directly to a private GitHub Issue within the developer's repository for manual review, in the same manner described in Section 2.4. The developer personally reviews each submission before deciding whether to add it to the public listings or reject it. ---------------------------------------- 2.6 Reserve Vehicle Driver Submission Data The application includes a "রিজার্ভ গাড়ি" (Reserve Vehicle) feature, available under the "এলাকাভিত্তিক সার্ভিস" section on the home screen, that allows users who work as vehicle drivers (CNG, auto-rickshaw, car, pickup, bike, or tractor) to voluntarily list themselves so nearby residents can book their service. When a driver submits this form, the following information is collected: their name, years of driving experience, ward number (1-9), phone number, WhatsApp number (optional), and address. Before submission, the driver must acknowledge a short terms-of-conduct notice describing expected behavior toward customers. This submitted information is sent directly to a private GitHub Issue within the developer's repository for manual review, in the same manner described in Section 2.4. The developer personally reviews each submission before deciding whether to add it to the public directory or reject it. Separately, when a customer chooses to contact a listed driver (via call or WhatsApp), the application displays a brief in-app safety notice reminding the customer that they may report any misconduct through the application's "অভিযোগ" (Complaint) section. This notice does not collect or transmit any information — it is shown locally on the device. ---------------------------------------- 2.7 Information We Do NOT Collect ---------------------------------------- আমাদের দেবিদ্বার does not collect, store, access, or transmit any of the following: - Phone numbers stored in the device contacts - Financial, banking, or credit card information - Background location data - Camera or microphone recordings - Browsing history or activity from other applications - Email addresses of users - Biometric data of any kind - Any personal data from children under the age of 13 - Any information from government websites or portals - Any information from official government databases ======================================== 3. HOW WE USE INFORMATION ======================================== Information collected within the application is used solely for the following purposes: - Displaying a personalized greeting with the user's name on the home screen - Showing union-specific local services, ward information, and provider directories - Processing delivery service requests by generating a location link - Saving and retrieving the user's favorite service providers for quick access - Improving the overall user experience and application functionality We do not use any collected information for advertising, marketing, profiling, or any commercial purpose whatsoever. ======================================== 4. DATA STORAGE AND PROCESSING ======================================== SharedPreferences: Stores user name, union selection, notification read status, and favorite providers locally on the device only. Offline JSON Asset Files: Service directories and community information are bundled within the application package and stored locally on the device. No internet connection is required to access this data. Cache Storage: Temporary update files downloaded from GitHub are stored locally on the device for performance improvement. These files contain only publicly available community service data, not any personal user information. WhatsApp: Delivery requests and feedback messages are shared directly through WhatsApp only when initiated by the user. The developer does not intercept, record, or store these messages. No Remote Database for Personal Preferences: The developer does not operate any remote server or database that stores the user's own personal preferences (name, union selection, ward number, or favorites) — this information remains on the user's device at all times, as described in Section 2.1 and 2.3. Community Directory Database (Google Cloud Firestore): The public community service directory (names, phone numbers, WhatsApp numbers, addresses, and optional photos of service providers, businesses, and drivers who have voluntarily agreed to be listed — see Section 8) is stored in Google Cloud Firestore, a cloud database service operated by Google. This directory data is the same publicly-viewable information previously distributed as public files; only the storage method has changed, to allow the directory to be updated more efficiently and reliably. This database does NOT contain any personal information about app users themselves (such as their name, union selection, or device data) — it only contains information about the service providers who have voluntarily agreed to be listed, as described in Section 8. Access to add, edit, or remove entries in this database is restricted to the developer through a separate, password-protected admin application (see Section 5.2). Submission Review Process: The voluntarily submitted provider information described in Sections 2.4, 2.5, and 2.6 ("Add Provider", "Add Listing", and reserve vehicle driver registration) is first sent to a private GitHub Issue for manual review by the developer, as explained in those sections and in Section 5. Once reviewed and approved, the submitted directory information (not the identity of the person who submitted it) is added to the Google Cloud Firestore database described above so it can be displayed within the application. ======================================== 5. Technology: This feature is a rule-based keyword matching system powered entirely by locally cached JSON files retrieved from GitHub. It does NOT utilize any form of Artificial Intelligence (AI), Machine Learning (ML), Natural Language Processing (NLP), or Large Language Models (LLMs) such as ChatGPT, Gemini, or similar technologies. The assistant does not learn, train, or improve from user conversations in any way. Data Processing: When a user submits a question or message, the application performs a simple keyword comparison against a pre-defined, static list of questions and answers stored in a JSON file. This process occurs entirely within the application on the user's device. No external AI API calls are made. Privacy: - All chat messages and questions entered by the user remain strictly on the user's device. - We do not transmit, store, log, or record any chat history, questions, or personal queries on any remote server, cloud platform, or third-party database. - Chat history is not retained after the user closes the application session. - No user profiling or behavioral analysis is performed based on chat interactions. No Personalization: The assistant does not personalize responses based on the user's private behavioral patterns, location history, or personal data. All responses are based solely on static, publicly available community information about Debidwar Upazila that has been pre-defined by the application developer. Doctor Finder Feature: The application includes a multi-step doctor finder flow within the assistant. Users may search for doctors by specialization and area. This feature: - Only displays information pre-loaded from a publicly available JSON file on GitHub. - Does not access any medical databases or official health registries. - Does not store or transmit the user's medical queries or health-related searches. - All displayed doctor information is sourced from community volunteers and public listings, and may not reflect current availability. Users are advised to verify information directly with the respective healthcare provider. ======================================== 5.2 ADMIN APPLICATION (Separate, Developer-Only Tool) ======================================== To manage and review the community directory described in Section 8, the developer uses a separate, private admin application (package name: com.amar.debidwaradmin) that is NOT publicly available on the Play Store and is used exclusively by the developer.
